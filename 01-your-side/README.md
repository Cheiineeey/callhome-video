## 1. 镜头：先问，不自动开

接通后在按键上方出一排「不开 / 前置 / 后置」，你选完就收起。状态有四种：

```swift
enum Camera { case unchosen, off, front, back }
```

- 选了后置就是后置。关了再开，记得你上次选的哪个（存 UserDefaults）。
- 翻转键要走同一个入口（`chooseCamera`），别直接调相机层的 flip —— 不然「上次选的」不会更新。
- 关着时你那一格是黑底加一个划掉的摄像机。
- 系统相机权限弹窗只在第一次点开镜头时出，去不掉。

## 2. 每一轮挑哪几帧给 ta 看

最简单的做法是你说完那一刻抓一帧。问题是你可能一路都想让 ta 看（「你看它在干嘛」），说完那刻镜头早移开了。

我们现在的做法：

- 窗口是「上一轮取帧之后到现在」。
- **名额按场景给，不按时长给。** 跟这一段第一张差得够多才算换了场景，每段挑运动最小（最清楚）的一张。单场景就一张；说超过 12 秒多给一张开头。6 张只是封顶。
- 帧在你说完时就和转写并行上传，不多等一轮。
- 每轮真发出去的几张在屏幕顶上「ta 看到的」闪 5 秒，你知道 ta 看见了什么。

## 3. 让 ta 主动看一眼 / 你钉住一帧

- ta 在回复末尾写 `⟪看一眼⟫`，app 擦掉不念，念完 0.7 秒后抓当下一帧再发一轮。你一开口就作废，连看最多一次。
- **长按你自己那一格 0.4 秒 = 钉住当下这一帧。** 不发消息，跟你下一句一起走：
  - 手感：轻震一下，那一格闪白 0.4 秒，角上出一个钉住张数的小标。
  - 最多钉两张，再钉挤掉最早的；同一帧重复钉不算两张。
  - 下一轮里钉住的排在最前，自动取的排后面，合计照样封顶。
  - 前缀写明哪几张是你钉的：「2张都是她长按钉住要我看的」或「前1张是她长按钉住的·后2张按先后取」。ta 得知道哪张是你特意给的。
  - 手势要用 `simultaneousGesture`，小窗身上还挂着拖动（见坑 1.4）。
  - 松手那一下用一个 `justPinned` 吃掉，不然小窗会顺手当成「点一下对调」。
  - 关镜头时钉住的跟缓冲一起清（坑 1.2）。
- 右上角「眼睛」键 = 钉住当下这一帧，并替你发一句「给你看」。长按藏得太深，我们自己都忘了有，所以摆了一颗明面上的。

## 4. 通话中打字

不方便出声时打字，ta 照样用声音回。

- 消息前缀标「打字」，网关告诉模型这是她打的、不是说的。
- ta 正在说话时打的字排队，不打断 ta。
- 画面要 `ignoresSafeArea(.keyboard)`，输入框单独跟着键盘走，不然键盘一弹整个画面被挤。

## 5. 实时灰字

你说话时屏幕上先出灰色的识别字，说完再换成服务器转写的正式那句。

- `SFSpeechRecognizer`，能本机就本机。VAD 判定开口才开始，说完 finish。
- 灰字**只给你看**，不送给服务器 —— 正式那句以服务器转写为准。
- 用一个代数计数挡住迟到的识别结果。
- ta 在出声时，VAD 起头先不开灰字，等确认是你插话再开（防回声）。
- 第一次会弹语音识别权限，不给就整条静默关掉。

## 6. 往回翻字幕

字幕区是整通的 `ScrollView`，贴底、顶上渐隐、最高 170pt。手指一拖进入「在翻」状态，松手 5 秒后才跟回最新一句。

## 7. 你安静时 ta 接不接话

你沉默 4 / 7 / 12 / 20 / 32 / 50 秒后 ta 会自己开口，之后每分钟一次。做成了开关（默认开），视频在右上菜单，语音在耳朵旁边。

## 这一章的坑

### 1.1 每轮都塞满上限 ✅
- **现象**：上限 6 张是给特殊情况的，结果几乎每轮 5~6 张，很多一模一样。
- **根因**：名额按时长给，窗口又从上一轮取完算起 —— 夹着 ta 想、ta 说半分钟，自然总是满。手持镜头抖动，每张都「不一样」。
- **修法**：改成按场景给名额（见第 2 节）。🟡 判断「换场景」的阈值还没校准。

### 1.2 关镜头之后，旧帧还被带上 🟡
- **根因**：关镜头时缓冲区里还躺着最后几帧。
- **修法**：关的时候在锁里当场清缓冲；抓帧、钉帧、取帧之前都先看「现在还要不要」。

### 1.3 关了再开永远是前置 🟡
- **根因**：开镜头键写死 `.front`；翻转键绕过了记录「上次选的」的入口；相机层换镜头也没回写当前朝向。
- **修法**：记一个 `lastLens`，开镜头用它；翻转统一走 `chooseCamera`。

### 1.4 长按钉帧一次都没成功过 🟡
- **现象**：服务端历史里一条「长按钉住」的前缀都没有。
- **怀疑**：小窗的拖动手势是 `minDistance: 0`，把长按吃了；或者全屏时上层控件盖住了。
- **现在的写法**：长按改挂 `simultaneousGesture`，跟拖动并存。另加了「眼睛」键做替代。**两条都还没在真机上看到钉住的帧到达服务端**，验过再改 ✅。

### 1.5 「上一句被加到这句开头」✅
三个原因叠在一起：
1. 兜底 VAD（25 秒没判出停顿就强制切句）切完从不清缓冲，下一次连上一句一起送。
2. 排队时已经上屏的半句，合并后又上屏一次。
3. 你在 ta 说话时插的那句只在「ta 写完」时冲出去；ta 先写完、后念完，就跳过了，卡到你下次开口才并进去。

### 1.6 咳一声刷出「没听清」✅
- **根因**：长话分段后，一小截（咳嗽、碰桌子，不到 0.45 秒）报 0 段，被当成整句失败。
- **修法**：最终且段数 > 0 才报。

### 1.7 沉默接话永不停 🟡
- 没有上限。你不在手机前，它会一直生成、一直进历史。所以做成了开关。

### 1.8 字幕只显示一两句 🟡
- 早期截前三行，长段后半看不见。改成整通可滚动后，字幕区开始接触摸 —— 要确认没挡住画面原有的点击。

### 1.9 咳一声之后，ta 再也不主动开口 🟡
- **现象**：你安静着，ta 本来几秒后会接话；你咳了一声，之后就一直沉默，直到你说出完整一句。
- **根因**：一出声就取消接话倒计时（对的）；可那一下要是被扔掉（太短）、转出来是空的、或者转写失败，**没有任何地方把倒计时挂回去**。
- **修法**：所有「这一下不算数」的出口都重新挂一次倒计时（前提是 ta 没在说、没在想）。

### 1.10 通话一分钟后，ta 听不见你了 🟡
- **根因**：`SFSpeechRecognizer` 单个任务有约一分钟上限；你一直不说话也会超时报错。任务结束后不重开，后半通就聋了，没有任何报错。
- **修法**：`isFinal` 或 `error` 都当这一句结束、立刻开新任务；报错那种隔半秒再开，识别器不可用时不隔会原地空转。最好每句开一个新任务。

### 1.11 你连说两句，ta 永远慢一拍 ✅
- **现象**：你说一句，停一下又补一句。ta 只回第一句；你说第三句时，ta 才开始回第二句。
- **根因**：ta 在想的时候你再开口，那句一律排队，等 ta 答完上一句再发。模型要想十几秒，你一句一顿地说，队列永远落后一句。
- **修法**：ta 还**一个字都没念出来**时你又开口，就把这一轮作废，两句并成一条重新问。
  - 作废时取消轮询，流式出来但还没念的字从字幕里撤掉。
  - 服务端新一轮进门会取消同一会话的旧轮次，连续两条用户消息并成一条。所以 app 只用补发新那句。
  - ta 已经有字在合成或在念了，就照旧排队。那时你听得到 ta 在答，打断反而乱。
- **已知的缝**：旧轮次恰好在「新那句落库」和「新一轮检查」之间写完回复，新一轮会以为已经答过而跳过。窗口很小，没堵。

### 1.12 咳一声，把 ta 想了一半的那轮挤掉了 ✅
- **现象**：1.11 之后，任何一点声音都会作废正在想的那轮，包括咳嗽、「嗯」、碰桌子。
- **修法**：先擦掉声音标签、语气词、标点，剩不到两个字的算「一下」：
  - 「一下」不作废这一轮。
  - 没有声音标签的「一下」（纯「咳」「嗯」），ta 在忙时直接丢掉。不然 ta 说完会单独发一轮，对着一声咳嗽回话。
  - 带声音标签的（开了「听你出的声」，听到喘、哭）照旧排队，等 ta 说完跟你下一句一起走。
